01 / MCP contract

Expose creation and exact lookup over stdio

The current CLI accepts a folder path for ingestion and a text query for ranked search.

ADR-0013 proposes a local tovli-mcp binary behind the mcp Cargo feature.

The initial MCP tools take a required source_key. A lookup returns a results array with zero or one committed memory.

The metadata object defaults to empty and has a proposed 4 KiB limit. Ranked MCP search and custom filters are deferred.

02 / Shared store

Let the CLI and MCP take turns accessing the store

The CLI folder orchestrator currently handles scanning, parsing, embedding, writing, and missing-file reconciliation.

The proposal extracts single-document processing for both the CLI and the MCP worker.

Each operation takes an exclusive lock and opens the needed handles. It checks recovery before serving data and closes the handles before releasing the lock.

An idle MCP session leaves the store available. If the CLI holds the lock, MCP waits up to five seconds before returning retryable store_in_use.

Folder reconciliation selects filesystem sources. It runs under the same lock as the rest of folder ingestion.

03 / Recovery

Recover a write before exposing the memory

Today, the vector insert can finish before the chunk map commits.

The proposal records intended chunk IDs before writing any index. The document and receipt become visible in one metadata transaction.

After interruption, the next CLI or MCP operation checks the journal under the lock. Unresolved recovery returns recovery_required.

04 / Image extension

Store original bytes and index the image text

The current parsers and embedder handle text inputs.

The image extension validates uploaded bytes and preserves the original under a full content hash.

An image document points to the asset. Its description, OCR, and context become text chunks for hybrid search.

Separate image memories can share one blob. Explicit fetch returns the original with its verified MIME type.

05 / Attachment contract

Keep relationships separate from document content

Current document records have no managed attachment relationship.

The proposal validates both document IDs and any optional chunk anchor before committing a link.

The endpoint and anchor tuple gives the link a stable identity. Each link stores its own caption.

Lookups traverse links in either direction. Deletion suppresses links and preserves shared image bytes.

06 / Rollout

Validate text before the image extension

Current releases ship the CLI without tovli-mcp.

Stage one requires the shared service, journal recovery, exact lookup, and the store lock.

Stage two adds the managed asset store and relationship records.

Verify rollback against a copy of the store. Compatibility with older binaries after new writes remains unverified.

Deployment risk: Unverified in runtime

Requirements

  • Build compatible CLI and MCP binaries.
  • Point --store-dir to the CLI workspace’s .tovli directory.
  • Use the temporary lock for every store operation.
  • Include asset files in image-store backups.

Rollback

Conditionally safe with a verified pre-rollout backup and no new data to retain. Compatibility after new writes is unknown.

Production verification

  • Use CLI search and ingestion while MCP stays connected.
  • Test lock waits and timeout in both directions.
  • Inject failures between writes and test recovery.
  • Verify byte-identical image retrieval and stale anchors.

Compatibility

  • The proposal stages text tools first.
  • Validate the pinned SDK and supported Rust version.

Unknowns

  • The proposed implementation and its runtime tests are pending. Diagrams and sample responses illustrate the ADRs.
  • SDK version compatibility, recovery latency, and rollback after new writes need implementation evidence.
  • Ranked MCP search, custom metadata filtering, and visual embeddings require later decisions.
